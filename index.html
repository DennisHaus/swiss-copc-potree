How it works

  1. Find tiles. The visible map extent is sent to the swisstopo STAC API, which lists the swissSURFACE3D tiles (1 km × 1 km) that intersect it. Each tile is a Cloud Optimized Point Cloud (COPC) file; tiles that only exist as a plain LAZ file are supported as well.
  2. View. Selecting a tile streams its COPC file into the Potree viewer. Only the parts needed for the current view are requested, up to the point budget you set under Appearance. A plain LAZ tile cannot be streamed: it is downloaded and decoded completely in the browser, and the point budget then thins it evenly.
  3. SWISSIMAGE colour. The swissSURFACE3D points carry no colour. For each point, its LV95 coordinate is converted to Web Mercator and one pixel is read from the SWISSIMAGE orthophoto (WMTS) covering the tile. That pixel becomes the point's RGB value.
  4. Sections. A horizontal or vertical box clips the cloud. Position and thickness are set with the sliders.
  5. Export. Export reads every node of the COPC file directly, so the result has the full point density and is independent of the viewer's point budget. The section export keeps only the points inside the section box. Files are written as uncompressed LAS 1.4 (point format 7) with a CRS record for CH1903+ / LV95.

Notes

  • The colour of a point is the SWISSIMAGE pixel it falls on. The pixel size is set with SWISSIMAGE resolution (up to the native 10 cm). Higher resolution means more tiles to download and more memory; it also applies to the export.
  • Large exports need time and disk space. Chromium-based browsers write directly to disk; other browsers assemble the file in memory first.
